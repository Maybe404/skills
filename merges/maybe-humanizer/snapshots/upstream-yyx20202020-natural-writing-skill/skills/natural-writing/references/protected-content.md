# Protected Content

Protect truth before style.

## Exact spans

Keep these verbatim unless the user explicitly requests normalization:

- Names, organizations, product names, and model identifiers
- Dates, times, money, percentages, measurements, counts, and versions
- URLs, email addresses, file paths, commands, flags, code, logs, and error messages
- Direct quotations, cited titles, issue numbers, and identifiers
- Contractual keywords and defined terms

## Semantic commitments

Preserve these even when their wording changes:

- Who performed an action
- Who approved, rejected, caused, observed, or owns an outcome
- Whether a statement is fact, estimate, allegation, opinion, or hypothesis
- Confidence, uncertainty, exceptions, conditions, and negation
- Evidence relationships: which source supports which claim
- Required, prohibited, recommended, and optional actions

## Procedure

1. Extract exact spans mechanically when files are available.
2. Mark semantic commitments manually.
3. Rewrite around the protected material.
4. Compare original and result.
5. Treat any unexplained change as a failed edit.

Do not “improve” a command, version number, quotation, responsibility statement, or technical term because a synonym sounds smoother.
