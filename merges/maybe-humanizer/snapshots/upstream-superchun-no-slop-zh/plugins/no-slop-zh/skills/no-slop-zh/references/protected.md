# Protected spans

改写前先区分两类保护：逐字锁定保护具体值与机器结构；语义锁定保护事实关系。不要把整句技术陈述都当成不可编辑文本。

## 逐字锁定

- 版本号、commit hash、发布号（`v1.8.0`、`abc1234`）
- 日期、时间范围、数字与单位
- 命令、代码块与 inline code
- 路径、URL 的目标、包名、镜像名
- 报错原文、日志行、栈片段
- 接口名、字段名、配置键、环境变量名
- 产品名、人名、组织名的原文写法
- 引号内的直接引用
- Markdown / 结构标记：front matter、fence、链接目标、脚注标签、标题锚点、表格列结构

锁定 span 本身，不自动锁定它两侧的标点和整个句子。

## 语义锁定

- 责任主体、归因与引用归属
- 因果、条件、时序与比较关系
- 限制条件和不确定性（可能、尚未验证、仅在…时）
- 系统/服务/组件的行为事实（「网关在超时后返回 504」）
- postmortem / PRD / release note 中的领域术语与状态含义

语义锁定允许修病句、连接词和语序，但改前改后必须表达同一个主体、行为、条件和确定程度。

## 处理原则

1. 先锁逐字项并记录语义不变量，再改姿态与空话。
2. 逐字项保持原值；语义项允许换表达，不允许改变事实关系。
3. 删除含保护项的句子前，先尝试句内降调；仍需整句删除时，按 scope 进入待确认清单。
4. 不确定某个词是否需要保留时，先区分标准技术术语与行业简称、内部说法或截短词。前者保留；后者按语境改成常见说法。仍无法判断且改写可能改变事实时保留原文，并在这影响编辑取舍时写入改动说明。
