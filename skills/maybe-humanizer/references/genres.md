# 体裁边界

分诊时先过这一份（process.md 的 ALL-PROC-001）。体裁定不下来时按 ALL-PROC-003 问一句，不猜。

### ALL-G-001 适用与不适用

适用：把已有的中文或英文文字改得不像 AI 写的，或只审不改地指出问题；包括段落、文章和长文的结构重写。

不适用：翻译；从零写作；只查错别字；繁体中文；未经授权替真人更换声口。

繁体中文不适用，是因为本次合并的四个上游没有一个覆盖繁体中文的用词习惯，声称适用会误导。

- 正例：“帮我把这段客服回复改得说人话一点”——属于改写请求，适用。
- 反例：把“把这段中文翻译成英文”当成本 skill 的任务处理。违反点：这是翻译，不在适用范围内。

### ALL-G-002 体裁叠加的限制

体裁在语体之上叠加限制：

- 正式文章：不用缩写，论证要有结构。
- 邮件：允许问候语和落款，不用 markdown 标记（ALL-P-003）。
- 营销文：段落短，给具体的利益点，结尾只放一个行动点。
- 技术文：保留代码块，术语精确（ALL-PROT-009），给数字不给形容词。
- 未指明：不叠加任何额外限制。

体裁不同会让同一条模式规则的结论相反：技术文里的术语重复要保留，营销文里的重复要删。因此体裁不明时先问。

- 正例：改一封邮件时输出里没有任何 `**` 记号，有问候语和落款。
- 反例：给一篇正式文章的改写稿里大量用 don't、it's，且论证没有结构。违反点：正式文章体裁不用缩写。

### ALL-G-003 虚构与创意写作不适用

小说和创意写作不适用本 skill 的模式表：那里的判别信号是叙事结构（未解决的支线、人物选择的模糊性、非线性结构），不是用词和标点。遇到虚构文本先说明模式表不适用，再问用户要不要继续。

- 正例：面对一份小说手稿，先说明这套模式表是给说明性文字用的，问对方要不要继续。
- 反例：用词汇和标点类规则去审一篇小说，把叙事上合理的重复用词判成 AI 痕迹。违反点：对虚构文本套用了不适用的标准。
