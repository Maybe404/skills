# 英译中

## 目的

翻译的对象是意思，不是词。中文读者读完译文，应该得到和英文读者完全相同的东西：同样的结论、同样的条件、同样的语气、同样的限定。做法是先弄清一句英文让读者知道什么、做什么，再用中文的句式把它说出来；不是把每个英文词换成对应的中文词。"hello = 你好"这类词对词的映射不是本 skill 关心的事。

中文有三个特点会在翻译时悄悄改变意思，本 skill 的大部分规则都是在对付它们：

1. 中文习惯省主语、省条件、省情态。英文的语法逼作者把"谁""什么时候""必须还是可以"写出来，中文不逼。省掉之后，一句描述可以被读成一句命令，一句命令可以被读成一句描述。
2. 中文没有形态变化。单复数、时态、第三人称动词都没有标记。英文靠这些标记区分"这是在描述一类人的行为"和"这是在要求你"，中文要靠加词补回来。
3. 中文的定义句需要显式标记。英文 "X substitutes A for B" 只能是描述；中文"X 用 A 替代 B"既可以是描述，也可以读成"（对于 X）请用 A 替代 B"。

指令文件（CLAUDE.md、系统提示、skill）的翻译标准最严：读它的是模型，每一处歧义都会变成不同的行为。

## 流程

1. 通读全文再动笔。确定三件事：文本类型（规则、说明、示例、UI 文案、报错原文）；读者是谁（模型、用户本人、团队、外部读者）；文本会被怎么用（放进指令文件、发给别人看、只给用户自己读）。
2. 逐句判断句子类型：定义、规则（祈使）、理由、例子、条件分支。翻译时保留类型，并用中文的显式标记把类型钉住。定义句加"所谓……就是……"，规则句加情态词，条件句把条件和动作分成两个分句。
3. 建人称表。you / I / we / the user / it / they 各对应什么，全文只用一套。指令文件常见的一套是：你 = 读文件的模型，用户 = 使用者，不出现"我"。翻译前先看用户已有的约定，有就沿用。
4. 翻译。按意思重组句子；长句拆短；主语、触发条件、动作对象、情态、失败分支写全；原文没有的比喻、强调词、量词、语气词一个都不加。
5. 术语和代码。术语保留英文原词，首次出现时括注它在这个上下文里的意思；代码、命令、路径、标识符、flag、环境变量、占位符原样不动，内部标点全部半角。规则见 references/glossary.md。
6. 自检。逐条过 references/checklist.md，改到全部通过。数字、阈值、次数、百分比逐个和原文核对——改写时最容易静默改掉的就是这些。可以运行 `python3 scripts/check_zh.py 译文.md --source 原文.md` 做自动检查。
7. 交付。给出译文，另附"不确定项"：原文本身有歧义的地方、无法确定的指代、你做了什么假设。原文含糊的地方不要替作者做决定，标出来问。

## 核心规则

**先弄清意思，再写中文。**翻译一句之前，用一句话回答"这句让读者知道什么或做什么"。答不出来就先查上下文，不要硬翻。

**补全省略。**英文里有的主语、条件、对象、情态、分支，中文一个都不能省。遇到"先跑测试再提交"这样的句子要问：总是跑，还是只在改了 src 时跑？跑失败了停下来问，还是自己修？原文有答案就写出来，没答案就列进不确定项。

**描述和命令不能互变。**英文第三人称陈述句（"the mannered writer produces…"）翻成中文要保留主语（"写这种文字的人……"），否则"不写 A 而写 B"会变成对读者的要求，方向正好相反。定义句加"所谓……就是……"或"……指的是……"。

**不加料，不丢料。**译文里每个论点、数字、限定词都能在原文找到对应；原文的每个论点、数字、限定词都能在译文找到对应。压缩可以合并句子，不能删条件、删论点。译者自己加的比喻、"一堆""本质上""纯粹""老老实实"这类词，全部去掉。

**例子按功能翻译。**原文举一个英文矫饰句作为反面例子，中文要举一个同样矫饰的中文句，让读者一看就明白"这就是不该写的样子"。把英文比喻直译过来（"earns its keep" → "赚足口粮"），读者看不出问题在哪。

**代词改名词。**它、其、这个、自己能指向两个以上东西时，写出名词。"已是 Opus 的自己做"可以读成"让那个 agent 自己做"，要写成"已经是 Opus 的，你自己做"。

**多义词按上下文选义。**follow-ups 在"后续查找"的语境里不是"追问"；check in with the user 是"向用户确认"，不是"签入"。容易错的词见 references/glossary.md。

**译文本身是样本。**一段规定"不用比喻"的规则，译文自己不能用比喻；模型会把规则文本当成风格样本来学。"命中""胜者""闸门""跑通"这类半比喻词在规则文件里也算比喻。

**标题的范围和内容一致。**规则管回复和文档两类，标题就不能只写"写作"。

**字数不是 token。**中文字数比英文字符数少一半以上，token 数通常持平或更多。不要用字数判断译文是否更省。
