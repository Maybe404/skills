# 英译中的坑

目录
- 第一部分：翻译规则文件时实际踩过的坑（第 1–22 条）
- 第二部分：还没踩到但会遇到的坑（第 23–58 条）

每条的格式：现象、错例、正例、处理办法。错例和正例大多来自把一份英文 CLAUDE.md 翻成中文的实际过程。用 scripts/check_zh.py 检查本文件会报出第 8 条和第 15 条的错例，那是故意保留的反面例子。

## 第一部分：实际踩过的坑

### 1. 定义句被读成祈使句

现象：英文用第三人称动词做定义（"Mannered prose substitutes metaphor for direct statement"）。中文"矫饰的文字用比喻替代直述"可以读成"（写矫饰的文字时）用比喻替代直述"，一句定义变成一句要求，方向相反。
错例：矫饰的文字用比喻和修辞替代直白的陈述。
正例：所谓矫饰的文字，就是该直说的地方偏要用比喻和修辞。
处理：定义句一律加标记，写成"所谓 X，就是……""X 指的是……"或"X 是指……"。

### 2. 省主语让描述变成指令

现象：英文 "the mannered writer produces 'a dial worth turning'" 有主语。中文省掉主语后，"不写 A，而写成 B"成了对读者的要求。
错例：不写"一个值得调整的参数"，而写成"一个值得拧动的旋钮"。
正例：写这种文字的人不写"一个值得调整的参数"，而要写"一个值得拧动的旋钮"。
处理：描述别人行为的句子必须带主语。检查办法：把句子单独拿出来读，问"这是在要求我，还是在描述谁"。

### 3. 情态丢失

现象：原文是一段说明，放进规则文件后需要变成要求，但译文里没有一句带"不要 / 必须 / 应当"。
错例：整段只有定义和解释，没有祈使句。
正例：段首加"你输出的所有文字都不矫饰。"
处理：规则文件里每条规则至少有一句带情态的祈使句。情态强度对照见 glossary.md。

### 4. 条件压缩成名词短语

现象：英文 "Already know the fix? Offer it as a suggestion" 是条件加动作。中文"已知修法作为建议给出"把条件压进名词，读者不知道"已知"是谁在什么时候知道。
错例：已知修法作为建议给出，验收另写。
正例：你已经知道怎么修时，把修法作为建议写进去，验收标准另写。
处理：写成"X 时，做 Y"，条件和动作各占一个分句。

### 5. 等号和符号当规则

错例：一个任务 = 一个可独立验收的结果。
正例：拆出来的每个任务都要对应一个可独立验收的结果。
处理：符号能表达关系，表达不了"要求"。规则用动词写。

### 6. "自己"指代不明

错例：已是 Opus 的自己做。（可读成"让那个 agent 自己做"）
正例：已经是 Opus 的，你自己做。
处理："自己"前面写清是谁。

### 7. 直译造出怪词

现象：英文一个动词有几层意思，直译成名词短语后中文不通。
错例：extend 译成"可扩展的行为"；swap 译成"不替换"。
正例："可以扩展的功能，不修、不优化、不扩展"；"不换成别的"。
处理：把英文动词还原成中文里实际会说的动作。一个英文词翻成两三个中文动词是正常的。

### 8. 一句两个冒号

错例：不再续用：新开 agent，附你写的汇总：原目标……
正例：不再续用，改为新开 agent，附上你写的汇总：原目标……
处理：一句最多一个冒号。多出来的改成逗号，或拆句。

### 9. 数字和阈值被静默改动

现象：改写时把"重试一次"写成"两次"，没有人注意到。
处理：翻译完成后，把原文和译文里的所有数字、百分比、次数列成两列逐个核对。`scripts/check_zh.py 译文 --source 原文` 会自动比对。

### 10. 压缩时丢论点

现象：为了短，把"读者看得出来""它同时也不精确"两个独立论点删掉，剩下的段落只说了"作者很窄"，没说"换个写法会变好"，规则的理由没了。
处理：压缩前先列出原文的论点清单，压缩后逐条核对。压缩只能合并句子，不能删论点、删条件。

### 11. 译文自己矫饰

错例："矫饰的作者不会老老实实写……""作者在台上表演，读者却要在台下受罪"——原文没有舞台比喻，也没有"老老实实"。
正例：它让读者更费力，好让作者有机会表演。
处理：译者不加原文没有的比喻、成语、强调词（本质上、纯粹、非要）、量词（一堆）、语气词。规则文本尤其如此，它会被当成风格样本。

### 12. 例子直译丢掉功能

现象：原文举 "earns its keep" 作为矫饰的例子，直译成"赚足了自己的口粮"，中文读者看不出这句哪里矫饰。
正例："这一点没有白占位置"——一个中文里同样矫饰的说法。
处理：例子按功能翻译。原文用这个例子想让读者看到什么，中文就找一个能让读者看到同样东西的例子。

### 13. 标题范围和内容不一致

错例：标题"写作"，内容管回复和文档。
正例：标题"文字"。
处理：翻译标题时对照正文，标题要覆盖正文管到的全部对象。

### 14. 术语没有括注

现象：resume 在文件里出现三次，读者不知道它指什么。
处理：术语首次出现括注中文，括注写它在这个上下文里的意思——resume（续用已有 agent），不写词典义（简历）。

### 15. 全角标点混进代码

错例：`git commit －m "msg"`（全角减号）；路径里的全角冒号。
处理：反引号内、代码块内、URL、路径、命令行里一律半角。`scripts/check_zh.py` 会报出来。

### 16. 人称混用

现象：同一文件里"我""用户""你"各指谁不固定；一段说"面向我的"，另一段说"向用户展示"。
处理：翻译前定人称表，全文只用一套。常见约定：你 = 读文件的模型，用户 = 使用者，不出现"我"。

### 17. 用字数衡量 token

现象：中文字数少一半，token 数持平或更多，"更短"是错觉。
处理：不用字数论长短。需要比较时估 token 或直接数。

### 18. 半比喻词

错例：命中、胜者、卖点、闸门、跑通、落地。
正例：符合、采用哪个、优点、审批点、能运行、完成。
处理：技术文本里这类词常见到不觉得是比喻，但规则文件要求不用比喻时，它们也算。

### 19. 列表项是裸名词短语

错例：直接读文件：已知路径；本会话已编辑过。
正例：以下情况直接读文件，不用 codegraph：已知文件路径；本会话里已编辑过的文件。
处理：列表前的引导句写清"以下情况做什么"，每项写成能独立理解的短语。

### 20. 动词缺对象

错例：要求 agent 找反例。
正例：要求 subagent 验证结论时找反例，不找支持证据。
处理：找什么的反例、验证什么、报告给谁，对象写出来。

### 21. 多义词选错

错例：follow-ups 译成"追问"，读者理解成用户的追问；原意是模型自己后续的查找。
正例：同一任务里后续的代码查找。
处理：一个词在上下文里指什么就翻什么，不用词典第一义。

### 22. 缺宾语

错例：在每个 subagent 的 prompt 里注明。（注明什么？）
正例：在每个 subagent 的 prompt 里注明 codegraph 可用。
处理：英文代词 it 指代的东西，中文写成名词。

## 第二部分：还没踩到但会遇到的坑

### 23. 否定辖域

"Not all tests are required" 是"不是所有测试都必需"，不是"所有测试都不必需"。"Don't commit any scratch file" 是"任何临时文件都不要提交"。翻译带 not 的句子先确定否定管到哪个词。

### 24. 无施事的被动句

"Tests are committed only where the task asks" 没说谁提交。中文要么补施事（"你只在……提交测试"），要么用"由……"。规则文件里补施事。

### 25. 单复数

中文没有复数标记。"agents" 涉及数量时加"多个""每个""所有"；"an agent" 涉及单个时加"一个"。"give each agent a file list" 的 each 不能丢。

### 26. 时态和体

"has been edited this session" 是"本会话里已经编辑过的"；"edited" 单独出现可能是"编辑了"也可能是"被编辑的"。用"已经""过""正在"把体补出来。

### 27. 逻辑连接词

unless = 除非；until = 直到……为止；only if = 只有……才；if and only if = 当且仅当；whenever = 每当；as long as = 只要；once = 一旦。这些词决定规则什么时候触发，翻错等于改规则。

### 28. 全称和存在量词

any 在否定句里是"任何……都不"，在肯定句里是"任意一个"；every / each 是"每个"；some 是"某些 / 有的"；either A or B 是"二选一"。

### 29. and / or

英文 or 多数是可兼的（A 或 B 或两者都）。中文"或"通常读成二选一。可兼时写"A 或 B，或两者都有"；互斥时写"要么 A，要么 B"。

### 30. 长句和语序

英文习惯先结论后原因、先主句后条件、定语从句后置；中文习惯先条件后结论、先原因后结果、定语前置。按中文顺序重排，拆成短句。一个英文长句拆成两三个中文句子是正常的。

### 31. 比较级

"denser than Fable 5" 要写成"比 Fable 5 更密"，比较对象不能丢。"fewer updates" 是"更少的更新"，要有"更"。

### 32. 冠词的指称

"the test" 指前面提到的那个测试，"a test" 是任意一个。指称重要时用"那个 / 这个 / 某个 / 任意一个"补出来。

### 33. 名词化的动词

compaction、dispatching、verification 这类词，中文用动词更自然："压缩上下文""派发""验证"。做主语时可以保留名词。

### 34. 假朋友和多义词

见 glossary.md 的表。最容易错的几个：check in（向某人确认，不是签入）、address（处理，不是地址）、hold（"the rule holds" 是规则成立）、scope（任务范围 / 变量作用域，看上下文）、surface（动词时是"暴露出来"）。

### 35. 平行结构

英文列表各项的词性一致，中文也要一致。不要一项是动词短语、一项是名词。

### 36. 语气和语体

技术文档不用"吧、呢、啊"，不用"我们"泛指（除非原文有 we），不用反问。英文的 please 在规则文件里不译。

### 37. 强调方式

英文用斜体、大写、助动词 do 强调，中文用加粗或调整语序，不用引号表示强调（引号在中文里表示引用或反讽）。

### 38. 引号、书名号、反引号

引用和举例用引号；书名、文章名用《》；代码、命令、文件名用反引号。不要用引号包代码。

### 39. 数字、单位、日期

数字用阿拉伯数字；百分比写 40%；日期写 2026-09-04 或"9 月 4 日"，全文一致。"by Friday" 是"周五之前"，不是"周五"。

### 40. 量词的方向

at most = 最多；at least = 至少；up to = 最多到；over / more than = 超过；under / less than = 少于；roughly / about = 大约。"over 40%" 和 "up to 40%" 是相反的阈值方向，翻错就是改规则。

### 41. 产品名和专有名词

Claude Code、Workflow 工具、Agent 工具、MCP 这类名字保留原文和大小写。

### 42. you 的两种用法

指令文件里的 you 通常是读文件的模型；说明文里的 you 可能是泛指读者。翻译前判断，指模型时写"你"，泛指时可以省略或写"读者"。

### 43. 列表式的隐含条件

英文规则常写成 "Path known: read directly"，冒号前是条件。中文要把"如果 / 当……时"补出来，或者用引导句统一说明。

### 44. 原文本身有歧义

不要替作者决定。两种读法都翻出来问用户，或者按上下文选一种并在不确定项里说明。

### 45. 排版结构

规则文件里换行和空行有语义（一行一条规则）。保持原文的换行、列表层级、标题级别、代码块位置。不要合并段落。

### 46. 缩写

e.g. = 例如；i.e. = 即；etc. = 等；vs. = 与……相比 / 对；aka = 也叫；N/A = 不适用；TL;DR = 一句话总结。

### 47. 量词

中文名词需要量词："a test" 是"一个测试"，"a rule" 是"一条规则"，"a call" 是"一次调用"。选对量词。

### 48. 反问句和设问

英文 "Already know the fix?" 是设问，中文写成条件句"你已经知道怎么修时"，不保留问号。

### 49. UI 文案

按钮用动词（"保存""删除"），标题用名词；中文通常比英文短，但按钮里不能换行；占位符 {name}、%s、{{count}} 原样保留；大小写规则不适用于中文，不要用空格模拟。

### 50. 代码注释

只在用户要求时翻译。保留注释符号和缩进；注释里的标识符、参数名不译；TODO / FIXME / HACK 标记保留。

### 51. 报错和日志

原文照贴，不翻译。需要解释时在后面另起一句用中文解释。

### 52. Markdown 结构

标题级别、列表符号、表格列数、链接目标不变。链接文字翻译，URL 不动。

### 53. 顺序词

first / then / next / finally = 先 / 再 / 接着 / 最后，顺序不能变。

### 54. 情态动词强度

must / shall = 必须；should = 应当 / 要；may / can = 可以；must not / never = 不得 / 不要；need not = 不必；might = 可能会。规则文件里 should 和 must 的区别有实际后果，不要都翻成"要"。

### 55. 虚拟语气和反事实

"would have" = 本来会；"if X were" = 假如 X（实际不是）。翻错会把假设当成事实。

### 56. 双重否定

"not uncommon" = 并不少见；"don't fail to" = 一定要。中文直接翻成肯定，意思更清楚。

### 57. this / that 指代整句

英文 this 常指前面整个句子或想法，中文写"这一点""这样做""这种做法"，不写"这个"。

### 58. 英文习语

"ship it" = 发布；"land a PR" = 合入；"green" = 测试通过；"red" = 测试失败；"pair programming" = 结对编程；"in the loop" = 参与其中；human-in-the-loop = 人在回路（AI 语境的固定译法）。
